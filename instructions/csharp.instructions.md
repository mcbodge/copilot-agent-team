# C# and .NET

Follow the repository's conventions first and common .NET conventions second.

## Design
- Least exposure: `private` > `internal` > `protected` > `public`.
- No new interfaces or layers unless they serve an external dependency or testing; don't wrap existing abstractions; no unused members or parameters.
- Reuse existing code; when fixing one method, check its siblings for the same issue.
- Never edit generated code (`*.g.cs`, `// <auto-generated>`).
- Comments explain why, never what; XML docs only where the repository requires them.
- User-facing strings follow the repository's localization approach.
- Records for DTOs; modern C# (file-scoped namespaces, pattern matching, switch expressions, raw strings, collection expressions) within the project's language version. C# 14 (.NET 10) adds extension members, the `field` keyword, `?.=`, implicit span conversions, and partial constructors and events.
- Before using a feature newer than the surrounding code, confirm the target framework and `LangVersion` (the `.csproj`, `Directory.Build.props`, `global.json`). Never change them, `Nullable`, or central package versions unless asked.
- Syntax you don't recognize may just be newer than you expect: compile it or check the docs before "fixing" it.

## Errors, security, resilience
- Guard early: `ArgumentNullException.ThrowIfNull`, `ArgumentException.ThrowIfNullOrWhiteSpace`; no blanket `!`.
- Precise exception types; never throw or catch bare `Exception`; never swallow errors; keep the cause.
- No secrets in code or logs; validate input at trust boundaries; least privilege.
- Timeouts, cancellation, and retry with backoff for I/O where it fits; structured `ILogger` logging with context; OpenTelemetry for traces and metrics.

## Async
- `Async` suffix; always await: no fire-and-forget, no sync-over-async (`.Result`, `.Wait()`).
- Accept and pass a `CancellationToken` end to end; cancelable delays; linked CTS + `CancelAfter` for timeouts.
- `ConfigureAwait(false)` in library code only; `Task` by default, `ValueTask` only when measured.
- `await using` for async disposables; return the task directly instead of a pass-through `async`/`await`.
- Stream large payloads (`HttpCompletionOption.ResponseHeadersRead`, `ReadAsStreamAsync`, `JsonSerializer.DeserializeAsync`).

## Performance
- Simple first; optimize measured hot paths; `Span<T>`, `Memory<T>`, and pooling only where it matters.
- EF Core: project to DTOs, `AsNoTracking` for reads, no N+1 queries, no client-side evaluation.

## Build and validate
- Prefer repository scripts (`build.ps1`, `Directory.Build.targets`), else `dotnet build`/`dotnet test` on the narrowest project.
- Build output locked (MSB3027/MSB3021) by a local app or debug session: stop that process by PID and rebuild; report it instead if it looks like someone else's active work.
- A change that compiles but is missing at runtime (for example a new DI registration): run `dotnet build-server shutdown`, then rebuild.
- Report commands run and their results, never raw output.
